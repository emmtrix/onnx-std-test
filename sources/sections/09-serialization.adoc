[[serialization]]
== Serialization

=== General

An ONNX <<model>> is serialized as a Protocol Buffers message.

[IMPORTANT]
.Editorial note
====
See the editorial note in Clause 2. The normative status of the Protocol Buffers encoding must be settled: this document either cites a dated specification or reproduces the required subset of the wire format.
====

=== Message definitions

[IMPORTANT]
.Editorial note
====
Reproduce the schema normatively. Options considered:

(a) Include the `.proto` source as a normative annex.

(b) Restate each message as a table of fields with wire tags and obligations,
with the `.proto` as an informative annex.

(c) Express the schema in an abstract syntax with a defined mapping onto
Protocol Buffers.

Option (b) is recommended: it is what ISO deliverables customarily do, it
survives a change of encoding, and it makes each field's obligation explicit,
which the `.proto` file cannot express.
====

=== External data

A tensor's contents MAY be stored outside the model file.

[IMPORTANT]
.Editorial note
====
Specify the resolution of external data references, including whether relative paths are permitted and how a consumer is to behave when a reference cannot be resolved. This clause has security implications and SHALL state them explicitly.
====

=== Canonical form

[IMPORTANT]
.Editorial note
====
Decide whether this document defines a canonical serialization. A canonical form is a prerequisite for signing and for reproducible model hashes, both of which have been requested by adopters, but Protocol Buffers does not guarantee a canonical encoding on its own.
====
